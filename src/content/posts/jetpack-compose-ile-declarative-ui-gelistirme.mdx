Son yıllarda, mobil uygulama geliştirme trendlerinde çokça hareketlilik görüyoruz. Mobil kullanım oranları ve cihazların kapasiteleri-kabiliyetleri her geçen gün artıyor. Artık kullandığımız her servisin bir mobil versiyonu da muhakkak mevcut oluyor. Sektörün mobil yönde ilerleyişi hızlanarak devam ediyor. Çok değil, bundan 3–4 sene öncesine kadar, bir mobil uygulama geliştirmek için bilmemiz gereken teknoloji ve yöntemlerin sayısı bugüne kıyasla çok daha azdı. Geliştirmemiz gereken özelliklerin sayısı artıyor ve bu özellikler, geliştirme esnasında çokça değişebiliyor. Uygulamalarımızı geliştirirken bir yandan kullandığımız metotlara sadık kalıp performanslı, okunabilir, ölçeklendirilebilir kod yazmamız; bir yandan da bu bahsettiğim isteklere cevap vermemiz gerekiyor. _Ne trendlerin peşinden koşup ana meseleyi ıskalayabiliriz ne de bu teknolojilerden bihaber geliştirme hayatımızı sürdürebiliriz._

Hâl böyle olunca, kullandığımız mimarilerde paradigma değişiklikleri oldu. Klasik MVC/MVP mimarileri yerine MVVM gibi daha _reactive_ bir yapıda olan mimariler tercih edilmeye başlandı. Bu paradigma değişikliğini kullanıcı arayüzü tasarlarken kullandığımız yöntemlere uyguladığımızda karşımıza Jetpack Compose çıkıyor. Google’ın 2019 I/O etkinliğinde tanıttığı bu kütüphane, Kotlin dilinin avantajlarını kullanarak _declarative_ bir yaklaşım ile kullanıcı arayüzü tasarlamamıza olanak sağlıyor. Öncelikle, yukarıda da değindiğimiz paradigma değişikliğini incelemeliyiz.

## Declarative vs Imperative

Klasik Imperative programlama tekniğinde, derleyiciye istediğimiz işlemin **nasıl** yapılacağını anlatırken, Declarative yaklaşımında **ne** istediğimizi beyan (declare) edip, bu işlemin nasıl yapılacağı ile pek fazla ilgilenmiyoruz. Bu ikisi arasındaki farkı ne kadar yazsam da bir kod örneği paylaşmak kadar faydalı olmayacaktır. O yüzden şöyle buyrun:

```kotlin
val numbers = listOf(1, 2, 3, 4, 5, 6, 7, 8)

// Imperative
fun sumEvens(): Int {
    var sum = 0
    for (n in numbers) {
        if(n % 2 == 0) {
            sum += n
        }
    }

    return sum
}

// Declarative
fun sumEvens() = numbers.filter { n -> n % 2 == 0}.sum()
```

Örnekte, bir liste içindeki çift sayıların toplamını döndüren fonksiyonu yazıyoruz.

Örnekten de anlaşılacağı gibi, aslında Declarative ve Imperative kavramlarının hudutları kesin çizgiler ile ayrılmış değil. Declarative olarak verdiğim örnek, tahmin edebileceğiniz gibi bir alt katmanda Imperative olarak çalışıyor. Yazdığımız kod ne kadar _declarative_ olursa o kadar kısalıyor; okunuşu kolaylaşıyor. Şimdi bu iyileştirmeyi arayüz tasarımında nasıl uygularız ve neden uygulamalıyız ondan bahsedelim.

## Mevcut Yöntem & Problemler

Android uygulamalarımızı geliştirirken kullanıcı arayüzü oluşturmak için `Activity`, `Fragment` ve `View` gibi sınıfların yanı sıra `layout`, `attrs` ve `style` gibi XML dosyalarını kullanıyoruz. Android tanıtıldığı günden bu yana cihazlar, ekran boyutları ve formları, uygulamaların yapabildikleri ve kullanım alanları gibi aklınıza gelebilecek bütün faktörlerde değişiklikler oldu fakat bizim kullandığımız bu metot aynı kaldı. Bu parçalı yapı, kodun okunmasını oldukça zorlaştırıyor ve basit bir `View` oluşturmak için yukarıda bahsettiğim parçaları kullanmak zorunda kalıyoruz. Aynı zamanda kullandığımız tasarım öğelerinin içinde bulunduğu `android.widget` paketi ancak SDK güncellemeleri ile elimize ulaşabiliyor.

## Jetpack Compose

Android ekibi, bu problemleri çözmek ve bizim Declarative bir yöntem ile arayüz tasarımı yapabilmemiz için Jetpack Compose kütüphanesini tanıttı. Bu kütüphaneyi geliştirirken `React` ve `Flutter` gibi yapılardan ilham aldılar. Şu an bu kütüphanenin geliştirici önizlemesi (developer preview) aşamasında olduğunu, canlıda olan uygulamalarımızda kullanmanın sakıncalı olduğunu belirtmeliyim. Bu kütüphaneyi sıfırdan Kotlin dili ile geliştirip `androidx.ui` paketi içinde bizlere sunuyorlar.

Şimdi bir örnekle bu kütüphaneyi nasıl kullandığımızdan bahsedeyim: Öncelikle, Android Studio’nun güncelleme kanalını `canary` olarak değiştirip en güncel versiyonu indirmemiz lazım. Yeni proje açarken `Empty Compose Activity` seçeneğini seçersek IDE bizim için gerekli kütüphaneleri projeye ekliyor. Jetpack Compose ile basit bir renk seçme uygulaması yapacağız. Ekranda _state_’ini tutmak istediğimiz veriyi `Model` annotation'ı ile işaretliyoruz. Yine compose kütüphaneleri ile elimize gelen bu annotation ile işaretlenen sınıfların _instance_'ları _observable_ hale geliyor. Input olarak bir `Model` alan compose _function_'lar, veri değişikliklerinde yeni veriyi ekrana çizer.

```kotlin
enum class Rgb {
    RED, GREEN, BLUE
}

@Model
data class ColorModel(
    var value: Float = 0.5f,
    val rgb: Rgb
)
```

Sonra bu `ColorModel` ile `ColorSlider` _function_'ını yazıyoruz. Ekranda gördüğünüz her bir Slider için bu _function_'ı kullanıyoruz. Compose function'ları iç içe koyarak view'ı oluşturuyoruz. Compose _function_ ancak yine başka bir compose _function_ tarafından çağrılabiliyor.

```kotlin
@Composable
fun ColorSlider(color: ColorModel) {
    Padding(padding = 16.dp) {
        Slider(
            position = SliderPosition(initial = color.value, valueRange = 0f..1f),
            onValueChange = { p -> color.value = p },
            color = when (color.rgb) {
                Rgb.RED -> Color.Red
                Rgb.GREEN -> Color.Green
                Rgb.BLUE -> Color.Blue
            }
        )
    }
}
```

Son olarak bütün `ColorSlider`'ları birleştirdiğimiz ve çıktıyı göstermek için `Surface` eklediğimiz _function_'ı yazıyoruz. Bu view'ı `Activity`'mizin `onCreate` metodunda çağırdığımızda işimiz bitmiş oluyor. Composable fonksiyonlar ile layout'u set etmek için `setContentView(layoutId)` yerine `setContent { }` _extension_'ını kullanıp, içinde composable function'ımızı çağırmamız yeterli oluyor.

```kotlin
@Composable
fun ColorPicker() {
    val red = ColorModel(rgb = Rgb.RED)
    val green = ColorModel(rgb = Rgb.GREEN)
    val blue = ColorModel(rgb = Rgb.BLUE)

    Column {
        ColorSlider(color = red)
        ColorSlider(color = green)
        ColorSlider(color = blue)
        Surface (modifier = Expanded, color = Color(red.value, green.value, blue.value)) {
            Text(text = "r(${red.value}), g(${green.value}), b(${blue.value})")
        }
    }
}
```

Bu yazıda, kısaca Jetpack Compose nedir ve niçin böyle bir şeye ihtiyaç duyuldu onu anlatmaya çalıştım. Kullandığımız _framework_’lerde soyutlama seviyesi ne kadar artarsa kod satır sayımız o kadar düşüyor; bu da okunabilirliği artırıp geliştirme sürelerini kısaltıyor; büyük takımlar halinde çalışırken bizlere kolaylık sağlıyor. Tabii şunu da unutmamak gerekir: Bir framework _declarative_ hale geldikçe bizim dikkat kesilmemiz gereken meseleler farklılaşıyor fakat ortadan kalkmıyor. Sonuç itibarıyla bizim verdiğimiz komut, bir yerde _imperative_ bir usul ile makineye giriliyor; biz sadece o nokta ile aramıza mesafe koymuş oluyoruz. Kullandığımız soyutlama araçlarını iyi tanımalı, sınırlarını ve yetkinliklerini bilmeli, bizim ilk bakışta göremediğimiz çalışma prensiplerini iyi bilmeliyiz ki bu aracı doğru kullanabilelim. Bir sonraki yazımda, bunu yine Jetpack Compose özelinde inceleyeceğim.
